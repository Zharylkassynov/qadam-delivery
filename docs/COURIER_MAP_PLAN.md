## Что сейчас

`CourierSharing` в `src/components/order-tracking.tsx` уже отправляет точку
примерно раз в 15 секунд. Но он существует только в деталях одного заказа,
требует кнопки «Передавать геопозицию» и выключается при сворачивании.
`qadam.courier_locations` хранит координаты конкретного заказа. Поэтому до
принятия заказа показать местоположение курьера сейчас невозможно.
На главной карте клиента пока отображаются только точки отправления и доставки.

## Предлагаемое поведение

1. Курьер включает «Я на линии». При первом использовании геолокации видит,
   кому будет доступна его позиция, и разрешает доступ на устройстве. Выбор
   сохраняется на сервере; действующий режим остаётся ограничен 8 часами.
2. Пока Mini App открыт и активен, одна общая служба получает координаты и
   отправляет их примерно раз в 15 секунд. Переключение экранов и принятие нового
   заказа не требуют новой кнопки. После возвращения или перезагрузки работа
   возобновляется при действующем согласии, смене и разрешении устройства.
   Отказ в разрешении не вызывает повторяющихся окон; есть действие для настроек.
3. До назначения клиент видит на существующей главной карте доступных курьеров:
   только одобренных, активных, на линии, без текущей доставки и со свежей точкой.
   Общая карта показывает примерную позицию с округлением на сервере примерно
   до 300 м, без имени, телефона, Telegram ID и точных исходных координат.
   Интерфейс прямо сообщает, что расположение примерное.
4. После назначения клиент видит точную последнюю позицию своего курьера на
   главной карте и в доставке. Точность GPS и время обновления остаются видимыми;
   данные других заказов и их адреса не раскрываются. Точное значение здесь
   означает полученную GPS-точку с её погрешностью, а не гарантию точности устройства.
5. Свежие точки общей карты обновляются примерно раз в 15 секунд и исчезают,
   если новых измерений нет более 90 секунд. Назначенный курьер остаётся видимым
   как последняя известная точка с предупреждением об устаревании. Выключение
   смены скрывает курьера с общей карты сразу и останавливает отправку новых точек.
6. Без GPS курьер может работать с заказами и получать уведомления, но на общей
   карте его нет. Статус объясняет причину: разрешение не дано, позиция получается,
   нет связи либо данные устарели. Нельзя показывать его как свежую движущуюся точку.
7. Завершение доставки останавливает обновление координат этого заказа. Если
   смена продолжается, свободный курьер снова может появиться на общей карте.
   История прежних заказов сохраняет свои последние точки.

## Граница работы в Telegram

Qadam убирает свои повторные кнопки включения для каждого заказа. Системное
разрешение всё равно нужно; срок его действия выбирает устройство/Telegram.
Обходить повторный запрос после отзыва или одноразового разрешения нельзя.

Свернутый или закрытый Mini App не гарантирует выполнение кода и обновление GPS.
Первый вариант рассчитан на открытый Mini App: сворачивание приостанавливает
отправку, возвращение автоматически возобновляет её при действующих разрешениях.
Показатель «на линии» для уведомлений и наличие свежих координат на карте —
отдельные состояния. Если нужна передача при заблокированном телефоне, отдельно
проверим вариант трансляции геопозиции в чате Telegram на Android и iPhone;
покупка VPS сама по себе это ограничение не снимает.

Документация: [Telegram LocationManager](https://core.telegram.org/bots/webapps#locationmanager),
[автоматические обновления в браузере](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition).

## Файлы и миграция

- Новая миграция `db/migrations/YYYYMMDDHHMMSS_courier_presence.sql`: последняя
  точка курьера независимо от заказа, время измерения и получения, точность,
  настройка передачи и дата согласия. Одна текущая точка вместо истории маршрутов;
  RLS и права только серверной роли. Применённые миграции не меняем.
- Новые `src/lib/courier-presence.ts` и API `/api/courier/location`,
  `/api/couriers/nearby`, с соответствующими маршрутами отдельного `backend/`.
  Сервер проверяет владельца точки, роль, активность, смену, согласие, давность,
  порядок измерений и частоту отправки. Общий ответ ограничен количеством точек
  и областью карты; приблизительные координаты формируются на сервере.
- `src/lib/locations.ts`, `src/lib/orders.ts`: текущая точка назначенного курьера
  попадает в его активные заказы без отдельных отправителей на каждый заказ;
  завершённые заказы больше не обновляются.
- `src/lib/device-location.ts`, `src/lib/telegram-client.ts`: единый источник GPS,
  контроль разрешений, остановка при скрытии и возобновление при возвращении.
  Где доступен браузерный `watchPosition`, используем подписку; в Telegram —
  поддерживаемый LocationManager. Проверяем поведение на реальных устройствах.
- Новый общий контроллер в `src/components/`, подключённый на уровне
  `delivery-app.tsx` или `delivery-workspace.tsx`, а не внутри страницы заказа.
- `courier-availability.tsx`, `order-tracking.tsx`: состояние GPS рядом со сменой,
  убираем обязательное повторное включение в каждом заказе.
- `customer-home.tsx`, `delivery-map.tsx`: несколько курьеров, свой назначенный
  курьер, время обновления, пустое состояние и ошибка. Сохраняем текущий дизайн
  Qadam и управление картой; обновление не сбрасывает выбранный масштаб.
- Уточнение текста передачи координат в правилах/политике и согласия для курьера
  перед публикацией: клиентам до назначения доступны примерные позиции.
- `docs/ROADMAP.md`, `README.md`, инструкция и готовый SQL с checksum.

## Тесты и ручные шаги

Обязательные команды перед сдачей: `npm run typecheck`, `npm test`,
`npm run build`, `npm run check:build`, `npm run test:e2e`.

Проверить серверные запреты подмены курьера, публикации без смены/согласия,
старых и будущих координат, частых запросов; порядок точек; скрытие занятого,
отключённого и неактивного курьера; округление в API общей карты; отсутствие
чужих контактов и точных координат; прекращение записи завершённого заказа;
RLS и права `qadam_app`.

В браузере: один запуск на смену, переход между экранами без остановки, смена
заказа без повторной кнопки, скрытие/возврат, перезагрузка, отказ в разрешении,
нет GPS, сеть и повтор отправки, истечение 8 часов, обновление карты у второго
аккаунта, исчезновение старых точек, размеры 320/360/390/1440 px.

Владелец: проверить на двух телефонах/аккаунтах — разрешить GPS курьеру, включить
смену, посмотреть карту клиента, немного переместиться, принять доставку,
свернуть и вернуть приложение, выключить смену. Проверка системных разрешений
на Android/iPhone необходима: подмена SDK в тестах не воспроизводит окна телефона.
GitHub остаётся за владельцем. Сервер покупать для этой доработки не нужно.
