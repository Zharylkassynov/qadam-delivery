## Проверенная цепочка

В настоящем Chrome на готовой сборке Telegram SDK получает синтетическую подпись;
далее используются реальные обработчики API и отдельная локальная PostgreSQL
`*_test`. Только Telegram Bot API и тайлы карты подменены локальными фикстурами.
Фотография проходит настоящий клиентский canvas, серверную обработку Sharp,
сохранение метаданных, приватную выдачу и завершение заказа.

- Создание с выключенным по умолчанию кодом и отдельным согласием на его включение.
- Фото: потерянный ответ после успешной загрузки, безопасный повтор без второй
  записи, блокировка завершения до сохранения, просмотр отправителем.
- Код: неверная попытка, правильное вручение, пять попыток и блокировка на сервере,
  защита повторов, перевыпуск и лимит три раза за час, приватность исходного кода.
- Отказ до забора, новое назначение администратором, удаление старой геопозиции,
  закрытие контактов прежнему курьеру, новая рассылка доступного заказа.
- Смена после забора требует подтверждения передачи/возврата. Гонки назначений
  сохраняют только одно решение. Цена, транспорт, телефон и занятость сохраняют
  ограничения автотарифа; автотариф в рабочем проекте не включался.
- Блокировка действует на ранее выданную сессию, действия, карту и геопозицию.
  Восстановление доступа сохраняется на сервере.
- Оценка один раз от отправителя, просмотр только автором и администратором.
- Истечение доступа к фото, в том числе во время скачивания у провайдера;
  прекращение отложенных сообщений и очистка ссылок.
- Прежние заказы завершаются с исходными требованиями. Интерфейс и API выдерживают
  повторное открытие и отсутствие связи; отдельный фронтенд работает через CORS.

## Интерфейс

Проверены ширины 320, 390, 768 и 1280 px в сценарии вручения, отсутствие
горизонтального переполнения, нативные поля с подписями, выбор оценки и ошибки.
Скриншоты клиента, вручения, отказа и управления визуально сопоставлены с
утверждённым локальным макетом. Сохраняются Onest, цвета и отступы Qadam.
Артефакты прогонов находятся в игнорируемых `test-results/` и `artifacts/stage-7/`.

## Рабочая инфраструктура

Все три миграции этапа применены в Supabase, SHA-256 совпадают с репозиторием.
Шесть новых таблиц имеют RLS и права только серверной роли. Проверены семь новых
индексов и совместимый со старой версией ключ уведомлений. Проверки через
session и transaction pooler под `qadam_app` прошли, TLS 1.3 проверен, права на
изменение тарифа отсутствуют, `automaticPricingEnabled:false`.

Security advisor не нашёл новых проблем. Сохраняется прежняя информационная
запись о журнале `public.qadam_migrations`: RLS без политик, доступ закрыт
намеренно ([описание проверки](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)).
Прежние информационные замечания об индексах не изменялись в этом этапе.

В Vercel три настройки созданы только для Production; ключ кода и ID канала
имеют тип sensitive. Значения секретов не включены в исходники, документы и
вывод проверки. Резервная копия нового ключа исключена из Git.

## Граница проверки

Владелец подтвердил приватный канал, право бота на публикацию и таймер 31 сутки
своей командой проверки. Реальная отправка фотографии в этот канал ассистентом
не выполнялась. Камера и галерея iPhone/Android, разрешение на сообщения и
реальное получение фото в Telegram требуют проверки владельцем после публикации.
GitHub и публикация кода остаются за владельцем. До этого этап не считается
проверенным на рабочих телефонах. Шаги — [STAGE_7.md](STAGE_7.md).
