# Этап 7.1 — проверка геолокации с навигатором

1 ноября 2026. Ветка `stage-7-1-courier-location`. Начало, локальный макет вместо
Figma и тексты согласия/политики утверждены. На iPhone владельца подтверждён пункт
«Транслировать геопозицию» в личном чате бота. Фоновая работа требует отдельного опыта.

## Что реализовано

Согласие Qadam на автозапуск GPS хранится на сервере с версией и временем.
Следующая смена использует его, если устройство сохраняет доступ. Пользователь
может выключить автозапуск для следующих смен или отозвать согласие и остановить
передачу. Mini App GPS работает только при активном приложении.

Для конкретного принятого заказа курьер отдельно разрешает использование
трансляции Telegram. Сервер ждёт новое собственное сообщение в личном чате бота
до пяти минут, затем связывает его с курьером, заказом и версией назначения.
В сессии используется один источник; GPS Mini App не перезаписывает выбранную
трансляцию. Сохраняется последняя точка, полная история перемещения не собирается.
Источник и время обновления Telegram явно подписаны; это не обещание точного
времени спутникового измерения или постоянной частоты обновлений.

Выключение линии, отзыв, ограничение доступа, смена назначения и завершение
закрывают привязку. Старое сообщение не открывает её заново. Qadam не умеет
останавливать отправленную пользователем трансляцию в Telegram: её нужно
самостоятельно остановить в чате. Действующая сессия ограничена сроком смены,
сроком Telegram и максимумом восьми часов; продление — через новое подключение.
Если поток пропадает, клиент видит прежнюю точку с предупреждением через 90 секунд.

## Серверные настройки

| Переменная | Значение для закрытой проверки |
| --- | --- |
| `TELEGRAM_LIVE_LOCATION_ENABLED` | `true` |
| `TELEGRAM_LIVE_LOCATION_PILOT_ONLY` | `true` |
| `TELEGRAM_LIVE_LOCATION_PILOT_IDS` | Согласованный Telegram ID курьера; хранится только в настройках API |

Без enabled возможность выключена. При pilotOnly доступны согласованные ID и
администраторы с действующим курьерским доступом. Массовое включение через
pilotOnly=false не входит в первоначальный опыт и выполняется после его оценки.
Настройки не должны попадать в Preview или приложение frontend. Используются
существующий бот, защищённый вебхук и PostgreSQL; новый сервер или подписка не нужны.
Автотариф этим этапом не включается.

Миграции: `20261101103834_courier_location_streams.sql`,
`20261101110107_location_stream_lookup_index.sql` и
`20261101112310_location_source_permissions.sql`. Применённые файлы не менять.
Готовый воспроизводимый SQL — `docs/sql/stage-7-1-location-streams.sql`.
Триггеры закрывают привязку при изменениях заказа/линии даже предыдущей версией API.

Все три миграции применены в Supabase, контрольные суммы сверены. Проверены RLS,
поколонковые права источника и работа через transaction pooler под `qadam_app`
с TLS 1.3. Настройки Vercel созданы только для Production; согласованный аккаунт
проверен на наличие действующего курьерского доступа. Код ждёт публикации владельцем.

## После публикации владельцем

1. В WebStorm закоммитить и отправить ветку. Открыть PR в main, дождаться зелёного
   CI, выполнить merge и дождаться Ready в Vercel. Коммит:
   `Add courier location consent and Telegram live tracking`.
2. Полностью закрыть и снова открыть Mini App. Включить линию, принять новый
   согласованный заказ команды. Для этого не требуется настоящая платная доставка.
3. В заказе открыть «Подключить трансляцию Telegram», отметить согласие и нажать
   «Разрешить трансляцию для заказа». Только после этого отправлять новое сообщение.
4. Открыть личный чат бота → скрепка / «+» → «Геопозиция» → **«Транслировать
   геопозицию»**, выбрать доступный срок. Разовая отправка точки не подходит.
5. Вернуться в Qadam. Должны появиться «Обновления из Telegram», время и счётчик
   принятых обновлений. Если за пять минут сообщения нет, повторить подключение.
6. Клиентским аккаунтом на втором телефоне открыть этот заказ. Отдельно убедиться,
   что клиент видит источник и свежую точку. Не присылать точные координаты в чат.
7. На телефоне курьера открыть 2ГИС кнопкой в заказе (если точка задана) или вручную.
   Пройти пешком несколько минут. Проверить, что у клиента обновляются координаты
   и время, а счётчик растёт. Повторить с заблокированным экраном.
8. Если обновления перестали поступать: проверить фоновые разрешения Telegram
   в iOS, интернет и срок трансляции. При необходимости разрешить фоновый доступ
   по системному запросу. Не считать неподвижную старую точку подтверждением работы.
9. В Qadam нажать «Остановить использование в Qadam». Затем в чате Telegram
   открыть своё сообщение и выбрать прекращение трансляции. В следующем заказе
   старое сообщение не должно подключаться повторно.
10. Проверить завершение и выключение линии: новые точки в закрытый заказ не
    поступают. Настройки геолокации позволяют отдельно отозвать согласие.

Для результата достаточно сообщить: iPhone/версия Telegram, выбранный срок,
сколько минут был открыт 2ГИС, были ли новые обновления при блокировке экрана,
появилось ли предупреждение о старой позиции. Физический тест обязателен перед
включением остальным курьерам.

## Вебхук

Скрипт настройки уже включает `message` и `edited_message`. Ассистент не запускает
команды с токеном. Если сообщения не приходят, владелец выполняет
`npm run telegram:check` и проверяет `allowedUpdates` и `lastErrorDate`.
Не отправлять токен или содержимое .env в чат. Переустановка вебхука не нужна,
если указаны оба типа событий. Не использовать getUpdates одновременно с вебхуком.

## Ограничения

Постоянное отслеживание не запускается одним системным разрешением Mini App.
Трансляцию в Telegram каждый раз включает сам курьер на выбранный срок. Qadam
не может гарантировать фоновые обновления на каждом устройстве. Если опыт с
2ГИС не подтвердит работу, сохранить честную последнюю точку и отдельно
рассмотреть мобильное приложение курьера с фоновым доступом.
