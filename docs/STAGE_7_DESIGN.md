## Визуальное решение

Сохраняются существующие токены Qadam: синий `#2455db`, текст `#122f43`,
вторичный `#526779`, фон `#f3f6fa`, поверхность `#ffffff`, линии `#dce5ef`.
Предупреждение `#a54b21`, ошибка `#ac2f35`, успех `#216548` используются по смыслу.
Шрифт Onest, заголовки 25–28 px, основной текст 16 px, пояснения 13–14 px.

Акцент — подтверждение передачи, а не декоративная статистика. Фото, код и
чекбокс фактического вручения собраны на одном экране. Основное действие
закреплено снизу, длинное содержимое прокручивается внутри. После выбора
фотографии предпросмотр компактнее, чтобы оставить место для кода.

Код отправителя — четыре крупных цифры с действием копирования. Курьер получает
только поле ввода и остаток попыток, администратор — объяснение ограничения.
Управление заказом — список действий с отдельным подтверждением причины;
опасные операции выделены красным. Действие после забора дополнено чекбоксом
согласованной передачи/возврата. Оценка — пять доступных с клавиатуры вариантов,
комментарий и пояснение о получателях отзыва.

```text
Курьер: В пути → Подтвердить вручение → Фото + выбранный код → Доставлено
                     ↘ Ошибка → Повтор / Новый код у отправителя / Команда

До забора: Отказ + причина → Снова в поиске → Другой курьер

Админ: Заказ → Действие → Причина + проверка текущего состояния → История
Клиент: Завершённый заказ → Оценка → Результат виден автору и команде
```

## Состояния и границы

Показаны: код/без кода, прежние условия заказа, камера и неподдерживаемый файл,
загрузка и ошибка, неверный код и исчерпание попыток, перевыпуск, завершение,
нет свободных заказов, нет подходящего курьера, отказ, назначение до забора,
передача после забора, конфликт изменения, отмена, блокировка/восстановление,
отзыв и истёкший доступ к фото. Шаблоны фото — SVG-схема, не настоящая фотография.

Клиентская кнопка не завершает заказ. Отказ доступен до забора; при передаче
посылки нужен действующий назначенный курьер. В макете это демонстрируется,
в реализации ограничения будут проверяться сервером, а не только кнопками.

## Проверки макета

Chrome: 39 состояний на 320/390/768/1280 px — 156 проверок размеров. Проверяются
страница, внутренний контент, нижние действия и расположение полей/кнопок.
Пройдены пять неверных попыток, перевыпуск и верный код, вручение без кода,
отказ, передача, отмена с обязательным подтверждением, блокировка/восстановление,
оценка и оформление без кода. Шрифт Onest загружен; внешних запросов и ошибок
JavaScript нет. После визуальной правки предпросмотра и добровольного включения
кода вся матрица повторно прошла. Просмотрены мобильные снимки подтверждения,
кода, передачи, оценки и блокировки, а также общая композиция на 1280 px.

Снимки и машинный отчёт сохраняются в игнорируемой папке `artifacts/stage-7/`.
Это проверка прототипа. Пять обязательных команд и настоящие API/SQL-сценарии
выполняются после согласования и реализации. В рабочем приложении новых функций
этапа 7 пока нет, миграция не применялась.
