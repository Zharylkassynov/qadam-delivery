# Telegram Mini App

Бот: [@qadam_delivery_bot](https://t.me/qadam_delivery_bot).
Адрес приложения: https://qadam-delivery.vercel.app.
Город демонстрации — Алматы. Адреса вводятся вручную, геолокация ещё не подключена.

## Подключение бота

1. Создать отдельного бота через официальный [BotFather](https://t.me/BotFather),
   команда `/newbot`. Не использовать токен другого проекта.
2. Скопировать `.env.telegram.example` в `.env.telegram`. Ввести токен и username
   только в этот локальный игнорируемый файл, установить публичный APP_ORIGIN.
3. Выполнить `npm run telegram:check`. Команда проверяет getMe и показывает только
   username и настройки меню, не выводит токен.
4. После проверки кода применить новую миграцию из `db/migrations` к облаку
   административным подключением. Runtime использует ограниченную роль qadam_app.
5. В Vercel Production сохранить TELEGRAM_BOT_TOKEN как Secret, задать
   TELEGRAM_AUTH_ENABLED=true и опубликовать изменения. В Preview токен не задавать.
6. Выполнить `npm run telegram:connect`. Команда проверяет принадлежность токена
   боту, устанавливает и перечитывает кнопку меню «Открыть Qadam» с HTTPS-адресом.
   Она не отправляет сообщения пользователям и не настраивает рассылки/webhook.

Main Mini App в профиле и прямая ссылка `?startapp` — необязательная отдельная
настройка BotFather. Для текущего теста используется кнопка меню внутри чата.
Если включать Main Mini App: `/mybots` → бот → Bot Settings → Configure Mini App,
указать тот же HTTPS-адрес. URL, открытый вручную в обычном браузере Telegram,
не заменяет запуск через кнопку Mini App с подписанными данными.

## Ручная проверка с одним Telegram-аккаунтом

1. На телефоне открыть бота и нажать «Начать» / Start, затем «Открыть Qadam»
   в меню чата. Ожидается автоматический вход без пароля, домашняя страница
   «Доставка по Алматы». В профиле видны имя, роль Клиент и Telegram ID.
2. На компьютере открыть https://qadam-delivery.vercel.app в обычном браузере.
   Войти `courier1@qadam.demo`, пароль учебного демо `QadamDemo-2026!`.
   Telegram-клиент и браузерный курьер — разные аккаунты приложения.
3. В Mini App нажать «Заказать доставку». Ввести тестовые адреса в Алматы,
   имя получателя и тестовый телефон. В комментарии написать «Ручной тест Telegram».
   «Проверить заказ» → проверить данные → «Подтвердить заказ». Записать номер QD.
4. На компьютере найти именно этот номер и адрес. Принять заказ. В Telegram
   в течение нескольких секунд должен появиться статус «Курьер назначен».
5. Курьер последовательно нажимает «Посылка у меня», «Начать доставку»,
   «Завершить доставку». Проверить каждый статус у клиента в Telegram.
6. Полностью закрыть Mini App. Снова открыть через меню бота → «Заказы» →
   «Завершённые». Заказ должен сохранить номер, курьера и шесть событий истории.
7. Выйти из аккаунта Mini App, снова нажать «Войти через Telegram».
   В течение часа вход можно повторить; если данные устарели — закрыть приложение
   и открыть через бота. Telegram ID и история должны остаться прежними.
8. При необходимости повторить в Telegram Web. Открытие iframe разрешено
   только приложению и https://web.telegram.org; вход не зависит от cookie.

Два устройства с одним Telegram-аккаунтом откроют одного пользователя приложения.
Для проверки клиента и курьера именно внутри Telegram нужны два разных аккаунта.
После входа второго участника администратор подтверждает его ID и назначает
COURIER на сервере; пользователь не выбирает себе роль в Mini App.
Новые Telegram-аккаунты не получают доступ к заказам общих демоклиентов.

## Автоматическая проверка и ограничения

`npm test` проверяет подпись, подмену/срок данных, повторный конкурентный вход,
серверные роли, отключённый аккаунт и историю завершённой доставки.
`npm run test:e2e` проверяет настоящий локальный интерфейс; Telegram SDK и его
initData подменяются явно тестовыми, все запросы с cookie удаляются. Проходят
создание заказа, доставка браузерным курьером, повторное открытие, история и выход.
Синтетические Telegram-сценарии исключены из проверок облака/публичного сайта.

В Supabase приватная таблица qadam.telegram_identities закрыта от Data API и
защищена RLS. Runtime имеет SELECT/INSERT этой таблицы и INSERT только трёх
колонок users; он не назначает роли и не активирует отключённые аккаунты.
Supabase Security Advisor сохраняет прежнее INFO про отсутствие политик у
public.qadam_migrations: доступ к административным метаданным намеренно запрещён.

Сессии случайные, в БД сохраняется только SHA-256. Bearer токен Mini App хранится
только в памяти, не в URL/localStorage/sessionStorage. Проверка подписи выполняется
на сервере официальным алгоритмом HMAC-SHA-256; initDataUnsafe не используется.
Карта, координаты и фоновое отслеживание не добавлены в этом этапе.

Источники: [Telegram Mini Apps](https://core.telegram.org/bots/webapps),
[настройка меню бота](https://core.telegram.org/bots/api#setchatmenubutton).
