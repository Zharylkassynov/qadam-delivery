## Сервер, права и приватность

Новые 12 серверных сценариев проверяют явное создание ссылки только владельцем,
устойчивость к одновременным повторам, отзыв и замену секрета, истечение,
ограниченный публичный ответ, сюрприз, отдельное версионированное согласие,
свежесть обеих дат позиции, смену курьера, блокировку, завершение и отмену.
Обычный ответ заказа не содержит секрет ссылки; публичный ответ не содержит
адресов, контактов, внутренних ID, открытки, фото или кода вручения.

Есть проверки ограничения запросов с невалидными секретами, сохранения
счётчиков после отказа, закрытой области тайлов, отсутствия секрета ссылки
в запросе поставщику и прежней общей квоты карты. Поставщик в серверных
тестах подменён; реальные ключи и сторонняя сеть для новых сценариев не нужны.

Права таблицы разрешения проверены настоящим `SET LOCAL ROLE qadam_app`:
SELECT/INSERT/UPDATE и RLS. Локальная проверка создаёт роль при необходимости
только внутри откатываемой транзакции; это не проверка облачных прав Supabase.

## Браузерные сценарии

Новый сценарий совмещённого приложения проходит через настоящий локальный API
и БД: отправитель создаёт/копирует ссылку, проверяется подготовленный адрес
WhatsApp; другой браузер открывает страницу без входа и Telegram SDK.
Курьер разрешает показ отдельным действием, получатель видит позицию после
забора; устаревание, ошибка связи, повтор, отзыв разрешения, завершение
и отключение ссылки проверяются в интерфейсе.

Доступность карты и изображения тайлов подменены в браузере. Транспорт
Telegram и координаты тестовых аккаунтов синтетические. Это не доказательство
работы настоящего GPS, фоновой трансляции или Geoapify на телефоне.
Авторизация, статусы, разрешения, выдача/отзыв и публичные поля не подменяются.

Отдельный сценарий проверяет `frontend/` + `backend/`: публичную страницу
без SDK, CORS заголовка ссылки только у публичных маршрутов, запрет этого
заголовка для обычного API заказов и недоступность после отзыва.

Проверены размеры 320/390/768/1280 px без горизонтального переполнения.
Снимки реального приложения на 390/1280 px и устаревшее состояние просмотрены
и сопоставлены с утверждённым локальным макетом. Отдельное согласие управляется
клавиатурой; загрузка, сообщения ошибок и повтор доступны в сценарии.
Снимки сохраняются Playwright в `test-results/recipient-tracking-…/`.
Также просмотрены мобильные снимки отправителя со ссылкой и курьера с отдельным
согласием. Новый публичный сценарий отдельного frontend/API прошёл без входа
и запросов Telegram SDK.

## Исправления при проверке

- Уточнён поиск сообщения «Заказ создан» в прежнем сценарии: на странице теперь
  также есть отдельный доступный статус загрузки ссылки. Проверка повторной
  отправки заказа и отсутствия дубля сохранена.
- Новый запрос принятия заказа в тесте отправляет JSON, как требует действующий
  API. Поиск ошибки ограничен сообщением приложения, исключая служебный
  announcer Next.js. После отзыва согласия сценарий ждёт подтверждения сохранения.
- При открытии заказа по ссылке сценарий ждёт именно экран деталей, прежде чем
  открывать настройки: до загрузки заказа доступен главный экран с такой же
  кнопкой. Проверка больше не нажимает настройки уходящего главного экрана.
- Срок завершённой ссылки сравнивается с неизменяемым событием PostgreSQL,
  а не с часами Windows: расхождение часов Windows/Docker в несколько миллисекунд
  делало проверку нестабильной. Точное равенство событию + 24 часа проверяется.
- Единичный таймаут прежнего сценария смены перепроверен отдельно успешно;
  скрытого повторного запуска или увеличения общего числа попыток не добавлено.
- Прерванный длительной паузой полный прогон не засчитывается как успешный.
  После восстановления локального Docker выполнен новый прогон целиком.

## Что остаётся после локальной сдачи

До публикации применить SQL в Supabase и проверить его контрольный результат.
Затем владелец отправляет код через GitHub; после зелёного CI проверяет телефоны
по [инструкции этапа 8](STAGE_8.md): открытие без Telegram, переход в настоящий
WhatsApp и ручная отправка, фактический GPS, отзыв и сюрприз.
Ни эти ручные проверки, ни публикация в данном протоколе не объявляются выполненными.
