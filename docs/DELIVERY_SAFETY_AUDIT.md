# Проверка текущей защиты передачи

10 ноября 2026. Ветка `stage-9-delivery-safety`. Проверка выполнена на отдельной
локальной `_test` БД с вымышленными аккаунтами. Реальные API-пользователи,
местоположения и посылки не использовались.

Курьер передал свежую позицию в десятках километров от обеих точек заказа.
Серверное требование свежего GPS при принятии заявки выполнено.
Для заказа без выбранного кода и фото получен результат:

| Путь | Забор издалека | Завершение издалека |
| --- | --- | --- |
| `transitionOrder`, обычный endpoint статуса | Разрешён | Разрешено |
| `completeOrder`, endpoint подтверждения | Разрешён | Разрешено |

Это подтверждённый пробел. Удаление кнопок не закрывает его. На обоих путях
нужны общая проверка места и независимое подтверждение передачи.
Коды и фото, уже обязательные для отдельных заказов, проверяются; проблему
создают необязательность защиты для остальных заказов и отсутствие проверки
места при переходах. Автоматические тесты должны проверять защищённый режим
отдельно от прежнего сценария совместимости.

Локальный журнал: `artifacts/delivery-safety-audit.log`. Временные аккаунты
и их заказы удалены после проверки. Этот документ фиксирует исходное состояние,
а не готовность исправления. [План](DELIVERY_SAFETY_PLAN.md).
