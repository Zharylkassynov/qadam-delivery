## Подготовлено

- Вебхук `/api/telegram/webhook`: секрет в заголовке, лимит 64 КБ, сохранение
  `update_id` до ответа, обработка после ответа через `waitUntil`.
- Приветствие `/start`, ссылки в приложение, проверенный контакт из Telegram,
  разрешение сообщений и одобрение заявки действующим администратором.
- Сохранение подписанного источника перехода и новых полей анкеты, обязательные
  подтверждения возраста и согласия; старые заявки остаются читаемыми.
- Уведомления сохраняются в БД вместе с заявкой/решением, отправляются после
  COMMIT. Ошибка отправки не отменяет решение. Повторы ограничены и защищены
  от одновременной обработки. Ответ 403 отмечает запрет сообщений.
- API списка одобренных активных курьеров, доступный только администратору.
- Режим `npm run telegram:webhook` для настройки бота владельцем.
- [Утверждённые правила и политика](STAGE_2_TEXTS.md). Оператор — Команда Qadam,
  поддержка и удаление — [@zharlkssnv](https://t.me/zharlkssnv).

## Ограничение повторов уведомлений

Обработка запускается вебхуками, отправкой/рассмотрением заявки и запросами
профиля Telegram. Временная ошибка оставляет сообщение в очереди с задержкой;
очередную попытку запускает следующий такой запрос. Отдельного периодического
планировщика в этом этапе нет. После восьми неудач или ответа Telegram 400/403
сообщение не отправляется повторно автоматически. Актуальное решение всегда
сохраняется в приложении. Успешно обработанный payload обновления и тело
отправленного сообщения очищаются, идентификаторы остаются для защиты от повторов.

## Публикация владельцем

1. В WebStorm проверить ветку `stage-2-courier-bot` и закоммитить изменения.
   Текст коммита: `Add courier onboarding and Telegram bot`.
2. Отправить ветку на GitHub и открыть Pull Request в `main`.
3. Дождаться зелёной проверки CI и выполнить merge.
4. Дождаться успешной Production-публикации в Vercel. Новая версия должна
   показывать страницы `/rules` и `/privacy`.

## Ручные шаги после публикации

1. В BotFather открыть `/mybots` → @qadam_delivery_bot → Bot Settings →
   Configure Mini App. Включить Main Mini App и указать
   `https://qadam-delivery.vercel.app`.
2. Секрет вебхука уже настроен в Vercel и сохранён локально. На этом компьютере
   его не нужно копировать или выводить. При настройке на новом компьютере
   восстановить защищённую локальную копию либо задать одинаковый новый
   `TELEGRAM_WEBHOOK_SECRET` в Vercel Production и `.env.telegram`. Перепубликовать
   приложение после смены секрета. Не присылать секрет в чат.
3. После публикации выполнить `npm run telegram:webhook`. Команда использует
   локальный токен, настраивает `/start`, вебхук и выводит только проверочную
   информацию. При установке вебхука старые ожидающие события Telegram удаляются.
4. Администратору открыть бота и отправить `/start`, чтобы получать новые заявки.
5. Открыть ссылку `https://t.me/qadam_delivery_bot?startapp=courier_uni`
   другим Telegram-аккаунтом. Проверить анкету, передачу номера, отправку,
   сообщение администратору, одобрение и сообщение кандидату.
