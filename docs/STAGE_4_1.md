# Этап 4.1: автоматическая геолокация и карта курьеров

Ветка `stage-4-courier-map`. Владелец утвердил [план](COURIER_MAP_PLAN.md),
[локальный макет](design/stage-4-1.html) вместо Figma после исчерпания Starter
и [тексты согласия/политики](STAGE_4_1_TEXTS.md).

## Как работает

- «Я на линии» по-прежнему действует 8 часов и управляет уведомлениями.
  Геолокация требует отдельного первого согласия и разрешения устройства.
  Старые включённые смены не считаются согласием на показ позиции.
- Курьер включает передачу один раз. Общий контроллер работает на всех экранах
  примерно раз в 15 секунд. Переход в профиль, список или другой заказ не
  выключает его. При сворачивании отправка приостанавливается; при возвращении
  и перезагрузке возобновляется с действующим разрешением. Если разрешение
  отозвано, повторяющихся системных запросов нет: интерфейс предлагает настройки.
- Без геолокации доступны заказы и уведомления. На общей карте такого курьера
  нет. Выключение смены прекращает новые точки и сразу исключает его из выдачи.
- Главная карта клиента показывает свободных, активных, одобренных курьеров
  на линии с измерением не старше 90 секунд. Сервер округляет координаты примерно
  до 300 м и группирует совпавшие ячейки. В ответе нет имён, телефонов, внутренних
  или Telegram ID. Границы карты применяются после округления, чтобы ими нельзя
  было восстановить точные координаты.
- Карта работает в области Алматы; в одном ответе не больше 200 ячеек.
  Старые точки исчезают и при ошибке обновления. Движение карты не сбрасывается
  при обычном обновлении координат.
- После назначения заказчик видит GPS-точку своего курьера, её время и точность
  устройства на главной карте и в деталях. Занятый курьер скрыт с общей карты.
  Первый свежий фикс копируется при принятии; следующие обновляют все его
  активные заказы. Завершённая доставка сохраняет последнюю точку и больше
  не обновляется. Чужому клиенту точная точка заказа недоступна.

Mini App не гарантирует работу GPS после закрытия или блокировки телефона.
Срок системного разрешения определяется Telegram/устройством. Окна настоящих
Android/iPhone требуют ручной проверки; симуляция в браузере их не заменяет.

## Сервер и база

- `POST /api/courier/location`: `{sharing:true,consent:true}` включает согласие;
  `{sharing:false}` выключает передачу и удаляет текущую точку из общего состояния;
  `{latitude,longitude,accuracy,capturedAt}` публикует измерение только за своего
  курьера. Чужой `userId`, нет согласия, нет смены, отключённый аккаунт, старое
  или слишком будущее измерение отклоняются. Повтор старого измерения не
  возвращает маркер назад. Новая запись ограничена одним разом в 5 секунд.
- `GET /api/couriers/nearby?south=…&north=…&west=…&east=…`: только для вошедших
  клиентов, только приблизительные точки. Карта клиента запрашивает их раз в
  15 секунд. Открытая доставка сохраняет опрос раз в 3 секунды.
- Оба маршрута доступны также в отдельном `backend/`. Прежний маршрут записи
  позиции своего заказа сохранён для совместимости; интерфейс использует общий
  поток смены и не требует отдельной отправки для каждого заказа.
- Новая миграция `20261028053350_courier_presence.sql` хранит одну последнюю
  позицию на курьера, согласие и настройку передачи. История движения не собирается.
  Новая таблица закрыта от `anon/authenticated/service_role`, включён RLS;
  доступ имеет только серверная роль `qadam_app`.

28.10.2026 миграция применена в Supabase и проверена через рабочую роль с TLS.
Повторно выполнять её не нужно. [Готовый SQL](sql/stage-4-1-courier-presence.sql)
сохранён с записью `public.qadam_migrations`; SHA-256 исходного файла:
`08787d26076b2eef4253fe55c1e5e6c151a0f35de488adb648f5cd71792934b6`.
Новых секретов и платных сервисов не требуется.

## Шаги владельца после публикации

1. Закоммитить и отправить ветку, открыть PR, дождаться зелёного CI и объединить.
   Vercel автоматически публикует `main`. Миграция уже подготовлена.
2. На телефоне курьера открыть Qadam, включить «Я на линии», поставить флажок
   согласия и нажать «Разрешить геолокацию». Выбрать доступ на устройстве.
3. На другом аккаунте клиента открыть главную: увидеть примерную позицию курьера.
   GPS телефона может быть неточен в помещении; проверить время и погрешность.
4. Курьер переходит между профилем и заказами — передача продолжается. Затем
   принимает заказ клиента: клиент видит его GPS-позицию в своей доставке.
5. Немного переместиться и проверить обновление примерно за 15–20 секунд.
   Свернуть Qadam: через 90 секунд клиенту показана устаревшая позиция.
   Вернуться: отправка возобновляется без новой кнопки, если разрешение действует.
6. Завершить доставку и проверить, что её последняя точка осталась в истории.
   Выключить смену: курьер должен исчезнуть с общей карты и прекратить отправку.
7. Проверить отказ и отзыв GPS: заказы доступны, повторяющихся окон разрешения
   нет, интерфейс показывает состояние и переход к настройкам.

Команды с токеном Telegram владелец запускает сам. Если бот этапа 2 уже работает,
для этой доработки менять вебхук или настройки BotFather не нужно.

Текст коммита: `Add automatic courier location sharing and map`.

## Проверки перед сдачей

28.10.2026 прошли все обязательные команды: `npm run typecheck`, `npm test`
(84 серверных теста), `npm run build` (прежнее приложение и отдельный API),
`npm run check:build` (24 + 24 API-маршрута), `npm run test:e2e`
(32 сценария прежнего приложения и 3 с отдельным API; отдельная сборка фронтенда).

Проверены: серверное согласие, роли и активность, истечение смены, порядок и
частота точек, округление с фильтрацией по границам после него, доступ к точной
позиции своего заказа, общий поток для активных доставок и сохранение точки
завершённой доставки, RLS. Браузерные сценарии на двух аккаунтах проверяют
общую карту, принятие заказа, переходы между экранами, перезагрузку, паузу и
возобновление, отказ GPS без повторных запросов и вёрстку 320/360/390/1440 px.
Измерения и Telegram SDK в автотестах симулированы; физические устройства
проверяет владелец после публикации по шагам выше.

`npm run docker:up` применил одиннадцатую миграцию локальной базы, все три
контейнера healthy. `npm run docker:check` подтвердил тот же заказ после
перезапуска PostgreSQL, API и интерфейса. `npm run db:cloud:transaction:check`
подтвердил новую таблицу и права рабочего соединения Supabase с проверенным TLS.
