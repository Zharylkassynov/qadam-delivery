# Этап 8 — получатель и WhatsApp

6 ноября 2026. Ветка `stage-8-recipient-tracking`.
Начало этапа, локальная замена Figma, экраны и тексты утверждены владельцем.
Первоначальная проверка: typecheck, 167 серверных тестов, сборка, check:build
и 47 браузерных сценариев пройдены. 9 ноября подтверждена публикация кода;
пропущенное обновление рабочей базы применено при исправлении ошибки ссылки.
Остались публикация корректировок интерфейса и полный сценарий на телефонах.
Подробности — [исправление ссылки и ролей](ROLE_UI_FIX.md).

## Что добавлено

- В заказе отправителя — явное создание, копирование и отключение ссылки.
  Открытие WhatsApp готовит сообщение; отправку подтверждает человек.
- `/t/[token]` — обычная страница без входа, Telegram SDK и меню Mini App.
  Работает также в самостоятельном `frontend/` с отдельным API.
- Статус и желаемый интервал доставки; название магазина скрыто для сюрприза.
  Адреса, телефоны, сведения получателя, фото, открытка, код и внутренние ID
  не входят в публичный ответ и не загружаются в HTML этой страницы.
- В настройках геолокации курьера — отдельное разрешение получателю на имя
  и свежую позицию. По умолчанию выключено. Прежнее согласие не переиспользуется.
- Точная позиция доступна после забора и до завершения/отмены, при действующем
  назначении, отдельном согласии и передаче на смене. Проверяются и время
  измерения, и время получения сервером (90 секунд). Позиция прежнего курьера,
  заблокированного аккаунта и устаревшая точка не выдаются.
- При неудачном обновлении карта скрывается; последний статус отмечен временем
  успешной проверки. Опрос — раз в 15 секунд на видимой странице, после финального
  статуса прекращается. Отзыв/смена назначения действует на сервере сразу;
  уже открытая активная страница узнаёт об изменении при следующей проверке.
- Ссылка — 32 случайных байта. До 7 суток от выпуска, не дольше 24 часов после
  завершения/отмены по времени события, без продления при правке примечания.
  Отключение и повторное создание выпускают новый секрет. Старые заказы
  не получают ссылок автоматически.

## Проверка на телефонах

1. Отправитель создаёт обычный заказ, открывает его и нажимает «Создать ссылку».
   Ссылка должна сохраниться после повторного открытия заказа.
2. «Отправить в WhatsApp» открывает получателя и общий текст со ссылкой.
   Сначала проверить текст; реальное сообщение отправить самостоятельно.
   Если WhatsApp не установлен или номер не подходит, скопировать ссылку.
3. На другом телефоне или в приватном окне браузера открыть ссылку без входа
   в Qadam. Проверить статус, отсутствие адресов/номеров/открытки/кода.
4. Курьер принимает заказ. Открывает «Настройки геолокации» → «Отслеживание
   для получателя», явно подтверждает отдельный текст и нажимает
   «Разрешить показ получателю». До этого имени и координат у получателя нет.
5. До забора карта не показывается. После «Посылка у меня» и свежей геопозиции
   получатель увидит имя и карту. При отсутствии ключа/ошибке карты статус
   остаётся доступен. Учитывать интервал проверки до 15 секунд.
6. Проверить фактическую передачу GPS на устройстве. Прекратить обновление:
   не позже 90 секунд точка скрывается. Mini App не обещает работу в фоне;
   трансляция Telegram подключается по отдельным правилам этапа 7.1.
7. Курьер отзывает показ получателю. При следующей проверке имя и точка
   исчезают; передача отправителю отдельно не отменяется.
8. После доставки/отмены карты нет. Отправитель отключает ссылку: прежний
   адрес при повторном открытии недоступен. Проверить выпуск новой ссылки.
9. Отдельным заказом проверить «Сюрприз»: нет названия магазина, адресов,
   открытки и сведений отправителя. Ссылка сама сообщает о наличии доставки,
   поэтому отправитель решает, когда её передавать.

Секрет ссылки даёт доступ к ограниченным сведениям. Не публиковать реальные
ссылки в открытом GitHub или общих чатах и не включать их в сообщения об ошибках.

## Технические границы

Публичный API использует явный белый список полей, не сериализацию `Order`.
Секрет передаётся API и прокси тайлов отдельным заголовком `X-Qadam-Tracking`,
не параметром URL API и не сессионным токеном. Для отдельного API заголовок
разрешён только у соответствующих публичных маршрутов и только с допустимого
origin фронтенда. Авторизованные API по-прежнему требуют обычную сессию.

Страница и данные: `no-store`, `no-referrer`, `noindex/nofollow/noarchive`.
Не подключаются Telegram SDK и аналитика. Тайлы Geoapify запрашивает сервер,
не передавая поставщику секрет ссылки или сведения заказа. Допускаются только
тайлы вокруг свежей позиции действующего назначения; общие бюджеты карты
сохраняются. Дополнительные лимиты на минуту, секрет, технического клиента
и сутки применяются также к невалидным секретам. На обычном VPS до настройки
доверенного прокси используется общий консервативный анонимный лимит;
произвольному клиентскому `X-Forwarded-For` доверия нет.

`Referrer-Policy` снижает передачу URL сторонним сайтам, но секрет остаётся
частью открытой ссылки и может сохраниться в истории браузера или журналах
хостинга. Не подключать запись тел запросов/заголовков API; при выборе
производственного прокси исключить секретный путь `/t/…` из access-log.
Запрет индексации не заменяет секретность ссылки и её отзыв.
