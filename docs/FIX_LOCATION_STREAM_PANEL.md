# Повторы блока навигации в принятом заказе

4 ноября 2026. Исправление этапа 7.2 по сообщению владельца.
Ветка `stage-7-2-location-stream-fix`.

## Причина и изменение

В `OrderDetail` соседние `OrderLocationStream` и `OrderTrustPanel` получали
одинаковый React key: ID заказа и версию назначения. При обязательном фото
или коде оба компонента присутствовали одновременно. Во время обновлений
React мог оставлять лишние блоки «Позиция во время навигации» с состоянием
«Проверяем возможность подключения…».

Ключи дополнены разными префиксами `location-stream:` и `trust:`. Они остаются
стабильными при обновлении заказа и меняются при другом заказе или назначении.
Изменение находится в `src/components/delivery-workspace.tsx`; сценарий и
оформление ранее согласованного экрана сохраняются.

Миграции, настройки Vercel/Supabase и новые команды Telegram не нужны.

## Проверка

Новый сценарий `tests/e2e/location-stream-panel.spec.ts` использует настоящий
заказ с обязательным фото, локальный API и отдельную PostgreSQL `_test`.
Telegram SDK и аккаунты синтетические. Только ответы о доступности трансляции
задерживаются и задаются тестом, чтобы воспроизвести медленную сеть и разные
режимы функции. Фото и сообщения в настоящий Telegram не отправляются.

На прежней сборке проверка воспроизвела рост числа блоков до 19 вместо одного.
На исправленной сборке отдельный запуск сценария прошёл; мобильный снимок
с единственным блоком просмотрен.
Сценарий проверяет загрузку при обновлениях заказа, закрытый доступ, выключенную
функцию, повторное открытие и переход к следующему статусу. Также проверяется,
что галочка согласия не сбрасывается при обычном обновлении заказа, а блок
подтверждения вручения остаётся один.

| Проверка | Результат |
| --- | --- |
| `npm run typecheck` | Успешно |
| `npm test` | 155 / 155 |
| `npm run build` | Совмещённое приложение и отдельный API собраны |
| `npm run check:build` | 38 + 38 API-пакетов проверены |
| `npm run test:e2e` | 41 / 41 основного приложения + 4 / 4 отдельного API |

В первом полном прогоне после длительного перерыва получен таймаут проверки
карты. Полный повтор на той же сборке прошёл без ошибок; код карты и её тест
для этого исправления не менялись.

Логи и снимки до/после — в игнорируемом `artifacts/stage-7-2-location-stream-fix/`;
снимки сценария — в `test-results/`. Проверка выполнена в мобильном Chrome;
физический iPhone остаётся ручной проверкой владельца после публикации.

## Публикация владельцем

1. Закоммитить исправление и новый тест в текущей ветке, отправить её в GitHub.
2. Открыть PR в main, дождаться зелёного CI и выполнить merge.
3. После Ready в Vercel полностью закрыть Mini App и открыть заново.
4. Принять заказ с фото. Подождать несколько обновлений, выйти к списку и
   снова открыть заказ, затем отметить «Посылка у меня». Блок навигации должен
   оставаться один, а при отключённой функции — отсутствовать.

Коммит: `Fix duplicate courier navigation panels`.
