# Этап 8 — получатель и WhatsApp

6 ноября 2026. Начало и общий план утверждены владельцем. Ветка:
`stage-8-recipient-tracking`. Конкретный локальный макет вместо Figma и новые тексты **утверждены владельцем 6 ноября 2026**.

## Результат для пользователя

Отправитель в своём заказе создаёт ссылку, копирует её или открывает WhatsApp
с подготовленным сообщением. Отправку подтверждает сам отправитель. Получатель
открывает страницу в обычном браузере без Telegram и входа в Qadam.

Страница показывает статус, выбранный интервал доставки и, при отдельном согласии
назначенного курьера, его имя. Карта показывает только свежую позицию этого
курьера после забора посылки. На странице нет адресов, точки забора, маршрута
А → Б, телефонов, внутренних ID, текста открытки, фото или кода вручения.
У магазина без режима «сюрприз» может отображаться его название; в режиме
«сюрприз» не показываются ни название, ни сведения, раскрывающие отправителя.

## Сценарии и предлагаемые границы

1. Ссылка создаётся явно владельцем заказа. Старые заказы не получают публичную
   ссылку автоматически. Секрет — 32 случайных байта в base64url; не номер заказа.
2. Доступен отзыв и выпуск новой ссылки. Старая после этого не работает.
   Предлагаемый срок: максимум 7 суток от выпуска и не более 24 часов после
   завершения/отмены; в финальном состоянии координаты скрываются сразу.
3. Перед созданием отправитель видит, какие сведения будут доступны каждому,
   у кого есть ссылка. Для сюрприза отдельно предупреждаем об уведомлении получателя.
4. WhatsApp открывается через `wa.me` с номером получателя и общим текстом
   со ссылкой, без адресов и контактов в тексте. Кнопка не отправляет сообщение
   автоматически. Для некорректного международного номера остаётся копирование.
5. Курьер отдельно разрешает показ имени и свежей позиции получателю по ссылке.
   По умолчанию это выключено; прежнее согласие не считается новым. Отказ не
   отнимает принятую доставку и не закрывает профиль. Отзыв действует немедленно.
6. До `PICKED_UP` координаты получателю не выдаются. В `PICKED_UP`/`IN_TRANSIT`
   нужны действующее назначение, актуальное отдельное согласие и свежая точка
   не старше 90 секунд. После смены курьера точка прежнего не выдаётся.
7. При устаревании показывается время последнего измерения без координат.
   При сетевой ошибке уже отображавшаяся точка также исчезает по порогу свежести.
   Никакого обещания непрерывной фоновой геолокации.

## Реализация после утверждения экранов и текстов

- Новая миграция: секрет ссылки, даты выпуска/отзыва/истечения и отдельное
  версионированное согласие курьера. Применённые миграции не редактируются.
  Сохраняются RLS, ограниченные права `qadam_app` и контрольные суммы миграций.
- `src/lib/recipient-tracking.ts`: явная выдача/отзыв, проверка срока, белый список
  публичных полей и лимиты запросов. Нельзя использовать полный `Order` как
  публичный ответ или передавать его в HTML/RSC страницы.
- `src/app/t/[token]/page.tsx`, компонент получателя, API ссылки и чтения статуса;
  соответствующие страницы/маршруты самостоятельных `frontend/` и `backend/`.
- Кнопки в `delivery-workspace.tsx`, отдельное разрешение в настройках курьера,
  общие стили, дополнения правил/политики. Существующие экран и API карты требуют
  авторизации: для получателя нужен ограниченный доступ только к тайлам его
  действующей ссылки, без открытия поиска, маршрутов и общей карты курьеров.
- `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, запрет индексации,
  отсутствие внешней аналитики на странице. Не включать секрет ссылки в журналы,
  сторонние запросы, подписи карты и сообщения об ошибках.
- Опрос только видимой страницы, остановка после финального статуса, обработка
  сети/429/невалидного секрета. Ограничения действуют также на невалидные токены
  и запросы карты; общие бюджеты Geoapify сохраняются.
- README, ROADMAP, инструкция и результаты проверки этапа.

## Проверки

На отдельной `_test` БД: выдача только владельцу, повторный выпуск, отзыв,
истечение, отсутствие лишних полей, старые заказы, сюрприз, согласие/отзыв,
смена назначения, свежесть и завершение. Браузер: без сессии и Telegram,
маленький экран, отсутствие утечки через HTML/JSON, ошибка и восстановление,
ссылка WhatsApp, копирование, отдельный frontend/API.

Перед сдачей: `npm run typecheck`, `npm test`, `npm run build`,
`npm run check:build`, `npm run test:e2e`. Проверить также самостоятельную
страницу frontend. Показать запущенный интерфейс и сравнить с макетом.

## Ручные шаги и внешние сервисы

Владелец проверяет ссылку на другом телефоне без входа, отправку через WhatsApp,
фактические GPS/отзыв и приватность сюрприза. GitHub остаётся за владельцем;
при сдаче будет готовый короткий английский текст коммита.

Покупка сервера, перенос Production, отправка сообщений людям, включение
автотарифа и этап 7.3 сюда не входят. Этап 5 не помечается завершённым условно.
6 ноября инструменты Figma, Supabase и Vercel в сессии не предоставлены;
облачные изменения не выполнялись. Доступность повторно проверяется перед
соответствующей операцией; при отсутствии Supabase будет подготовлен готовый SQL.
