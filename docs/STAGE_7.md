# Этап 7 — вручение и управление доставками

Ветка `stage-7-delivery-trust`. Начало, локальный макет и тексты утверждены владельцем.
Согласованный срок: доступ к фото в Qadam — 30 суток, автоудаление в служебном
канале Telegram — один месяц (31 сутки). Автотариф остаётся выключенным.

## Что меняется

- Новый заказ после включения сервиса требует фото упаковки перед завершением.
  Клиент может дополнительно выбрать четырёхзначный код; по умолчанию он выключен.
- Курьер сохраняет фото, вводит выбранный код и подтверждает передачу. Пять
  неверных попыток блокируют завершение до перевыпуска кода отправителем/админом.
- До забора курьер может вернуть заказ в поиск с причиной. Прежние контакты и
  координаты перестают выдаваться, код обновляется, исполнители уведомляются снова.
- Администратор назначает/меняет курьера и отменяет заказ с причиной. После забора
  обязательно подтверждает согласованную передачу или возврат посылки.
- Ограничение доступа закрывает курьерские действия сразу, включая старые сессии,
  и выключает показ на карте. Текущий заказ требует решения диспетчера; клиентские
  доставки доступны. Восстановление не включает линию и геолокацию автоматически.
- Отправитель оценивает завершённую доставку один раз. Отзыв видят его автор и
  администраторы; публичного рейтинга курьеров пока нет.

## Подготовка сервера

Три неизменяемые миграции в `db/migrations/`: `20261031102814_delivery_trust.sql`,
`20261031135617_trust_foreign_key_indexes.sql`,
`20261101082749_notification_rolling_compatibility.sql`.
Воспроизводимый SQL с контрольными суммами — `docs/sql/stage-7-production.sql`.
Он предназначен для однократного применения к схеме этапа 6. Перед повторным
запуском проверить журнал `public.qadam_migrations`; применённые файлы не менять.
Третья миграция сохраняет совместимость уведомлений с предыдущей версией приложения.

1 ноября 2026 все три миграции применены в Supabase, контрольные суммы сверены.
Проверены RLS, отсутствие доступа клиентских ролей и операции ограниченной роли
`qadam_app`. Настройки Vercel созданы только для Production; до новой публикации
код этапа 7 в Telegram недоступен.

Только API / Production получает:

| Переменная | Назначение |
| --- | --- |
| `DELIVERY_PROOF_ENABLED=true` | Фото у новых заказов и возможность выбрать код |
| `DELIVERY_CODE_SECRET` | 32 случайных байта в виде 64 шестнадцатеричных символов |
| `TELEGRAM_STORAGE_CHAT_ID` | ID проверенного приватного служебного канала |
| `TELEGRAM_BOT_TOKEN` | Уже используемый серверный токен бота |

Ключ хранить как секрет. Его замена без процедуры переноса лишит доступа к ранее
выданным кодам. Резервную копию хранить отдельно от Git и перенести вместе с БД
при будущем переезде на собственный сервер. `.secrets/` исключён из Git.
Для созданного ключа сохранена локальная резервная копия
`.secrets/stage-7-delivery-code.txt`. Не добавлять её в коммит и не отправлять в чат.
В Preview и приложение `frontend/` эти значения не передавать. В локальном Compose
фото по умолчанию выключено; отдельный API использует те же обработчики.

Канал — приватный; бот администратор с правом публикации, автоудаление «1 месяц».
Проверка выполняется владельцем: `npm run telegram:storage:check -- "<ссылка на сообщение>"`.
Ожидается `ready:true`, `privateChannel:true`, `autoDeleteDays:31`, `botCanPost:true`.
Приглашения в канал, реальные ссылки/ID и токены в документацию не добавлять.

## Публикация владельцем

1. В WebStorm проверить изменения ветки, закоммитить и отправить её на GitHub.
   Короткий коммит: `Add delivery proof and dispatch controls`.
2. Открыть Pull Request в `main`, дождаться зелёного CI и выполнить merge.
3. Дождаться успешного Production deployment в Vercel. Настройки применяются
   к новой публикации. Старые заказы сохраняют прежние требования.
4. На телефоне полностью закрыть и снова открыть Mini App из меню бота.
5. Двумя аккаунтами создать новый заказ с кодом, принять и пройти до «В пути».
   Снять/выбрать фото, сохранить, проверить неверный код один раз, затем вручить
   с правильным кодом. Убедиться, что отправитель видит фото и может оставить отзыв.
6. Повторить короткий заказ без кода; проверить сохранение после закрытия Mini App.
   Проверить камеру/галерею на iPhone и, если доступен, Android. Получение фото
   сообщением требует разрешения на сообщения бота.
7. До забора проверить отказ с причиной. Администратором назначить другого курьера;
   прежний курьер не должен видеть контакты. Проверить ограничение и восстановление
   доступа на согласованном аккаунте курьера, затем вернуть рабочее состояние.

Проверять реальную платную доставку для этой проверки не требуется. Тестовые
заказы команды следует завершить или отменить с понятной причиной.

## Хранение и поддержка

API проверяет срок фото при каждом запросе, независимо от работы очистки.
Обработчик очереди Telegram очищает истёкшие ссылки при обработке заданий;
на отдельном API это выполняет постоянный worker. На Vercel без входящих событий
очистка метаданных может произойти позже, но выдача фото после 30 суток закрыта.
Telegram удаляет сообщения служебного канала по собственному таймеру 31 суток.
Ранее отправленные клиенту сообщения и сохранённые копии могут остаться.

При обращении об удалении администратор вручную удаляет соответствующее сообщение
канала и обрабатывает запрос по политике. Нельзя обещать физическое удаление всех
копий у Telegram. При недоступности фото завершение нового заказа блокируется:
связаться с командой, согласовать дальнейшие действия, не обходить подтверждение.

Выключение `DELIVERY_PROOF_ENABLED` влияет на последующие новые заказы. Оно не
отменяет обязательное подтверждение у уже созданных заказов и не заменяет
восстановление рабочего канала/секрета. Откат на код этапа 6 после запуска фото
небезопасен: прежний API не проверяет новые требования. Исправлять текущую версию.
