# Вручение без проверки геопозиции

11 ноября 2026. По запросу владельца, для проверки сценария без поездки в точку Б.
Корректировка текущего этапа 9 в `stage-9-courier-cleanup`; этап 10 не начинается.

## Поведение

- Принятие и подтверждение забора сохраняют существующие правила GPS.
- При вручении сервер и кнопка завершения не требуют свежей позиции,
  разрешения GPS или близости к получателю. Фоновый запрос геопозиции
  не блокирует поля и завершение вручения.
- Нужны подтверждённый забор, правильный шестизначный код получателя,
  отметка передачи и сохранённое фото, если оно обязательно для заказа.
  Проверки назначения, блокировки курьера, версии адреса, срока кода,
  пяти попыток и повторных запросов сохраняются.
- Подтверждение и статус сохраняются одной транзакцией. В новой записи вручения
  координаты, точность, расстояние, время измерения/получения и источник равны `NULL`;
  история явно сообщает, что геопозиция не проверялась. Существующие записи не меняются.
- Тексты правил и описания сохраняемых данных приведены к этому поведению.

## База и выпуск

Перед публикацией кода нужна миграция
`20261111071512_dropoff_without_gps.sql`. Она разрешает полностью пустые поля GPS
только для `DROPOFF`; для `PICKUP` вся контрольная точка обязательна.
Частичная запись геопозиции запрещена. RLS, права и защита смены статуса сохраняются.
Старый код совместим с миграцией, но продолжает проверять расстояние до публикации
нового выпуска. Новых ключей и настроек Vercel нет.

Миграция применена на отдельной локальной `_test` БД и в рабочем Supabase
`Qadam Delivery` с отдельного разрешения владельца от 11 ноября.
Контрольная сумма:
`b62cad904c1ab200a198c4b6261bf473fccf3e12af9d489e51d3887a26775edb`.
Подтверждены checksum, все семь nullable-полей GPS, действующее ограничение
полноты контрольной точки, RLS и политики. `qadam_app` может читать и вставлять
доказательства; обновление и удаление по-прежнему запрещены. Проверка Supabase
не выявила новых замечаний; прежняя информационная запись о закрытом журнале
`public.qadam_migrations` сохраняется.

GitHub — по принятому порядку владельца: commit → push → PR → зелёный CI → merge.
После публикации открыть Mini App заново и пройти вручение, находясь у точки А:
код получателя, фото при необходимости, отметка передачи, завершение, повторное открытие.

## Проверка

Пройдены `npm run typecheck`, все 201 серверная проверка `npm test`,
сборки совмещённого приложения, самостоятельного API и фронтенда,
`npm run check:build` (46 + 46 API).
Общий `npm run test:e2e` остановился до выполнения сценариев: порт 3100
занят другим локальным запуском. Он не останавливался; сценарий этой доработки
пройден отдельно на порту 3115 и через самостоятельные API/фронтенд на
3102/3103: обе браузерные проверки успешны. Проверены код, обязательное фото,
системная кнопка Telegram, обе темы и ширины 320/390/768/1280,
сохранение результата после перезагрузки; ошибок JavaScript нет.

Серверные сценарии проверяют вручение из точки А, отсутствие/устаревание/неточность
GPS, отключённую передачу и завершённую смену, сохранность требований забора,
обязательного фото и кода, идемпотентность и ограничения базы.
Браузерный сценарий с настоящими локальными API и PostgreSQL остаётся у точки А,
делает координаты устаревшими и неточными, отключает GPS в синтетическом Telegram SDK,
завершает доставку штатной системной кнопкой и проверяет статус после перезагрузки.
Этот же поток используется с самостоятельным API.

Текст коммита: `Allow delivery completion without dropoff GPS`.
